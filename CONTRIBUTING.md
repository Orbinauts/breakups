# Contributing

Issues and pull requests are welcome, and every pull request is reviewed. Keep a change small and focused, and check it the way CI will before you open it: `npm install`, then `npm run typecheck` and `npm test`, which need no network and no account.

A change to the ground truth is a change to its inputs, never to `data/breakups.json` by hand: edit `data/truth/hand.json` (a statement from a source, with its citation) or `data/truth/overrides.json` (a reviewer's decision, by name), run `npm run truth`, and commit the regenerated `data/breakups.json` and `docs/truth.md` with the input that changed. A new edition of a machine-read source arrives through `npm run truth:fetch`, which needs poppler's `pdftotext`, and the same rebuild. The tests rebuild the truth from the committed snapshots and fail when the committed file differs.

A change to what the detector decides needs the scorecard's word for it: with the Archive beside the repository (`npm run archive:download -- <years> --warmup`, or every year), run `npm run kpi -- --all` (the years in order, each from the states the one before ended with) and commit the regenerated `kpi/latest.json` and `kpi/latest.md` with the change (the per-year files under `kpi/years/` are working files the KPI workflow keeps as artifacts, not in git), then paste the Confirmed headline table and the validation tables of `kpi/latest.md` into the README's "How well it does", which the tests check cell by cell (the Confirmed line first, the parent-step tables after it); `docs/detector/events.md`, the per-event dissection, is written with the aggregate and is committed with it. The KPI workflow recomputes the aggregate from the release and refuses a change whose committed score it cannot make again.

A threshold of the Confirmed channel (the confirmation rules and the attribution's) is fitted on the even years offline: replay once with the rules off into a work directory (`npm run kpi -- --all --out kpi/work/<name> --param confirmDeltaVMinMps=0 ...`, as `docs/detector/d9-confirmed.md` gives it), then `KPI_DIR=kpi/work/<name> npm run kpi:sweep -- --attributions [--set name=value] [--show]` re-applies the rules from the attribution rows and scores the Confirmed line on the training years; the replay with the values chosen is the record.
